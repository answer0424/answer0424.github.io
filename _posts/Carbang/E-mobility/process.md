## 말소사실증명서 전달 프로세스 개발

> 공단에서 이메일로 보내는 차량 서류를 자동으로 수집하고 차량번호와 신청 건을 연결한 뒤 거래처가 내려받을 수 있도록 제공하는 서비스


#### 전체 업무 흐름

1. 담당자 Works 로그인
2. ACcess/Refresh Token DB 저장
3. 5분 주기 배치 실행
4. 공단 발송 메일 조회
5. 첨부파일 다운로드 및 저장
6. 문서 종류/차량번호 식별
7. 기존 말소 신청 건과 매핑
8. 거래처 조회용 별도 API 제공
9. 만료시간이 있는 다운로드 URL 반환

<br>

#### 핵심 부분

- Works에서 공단 메일과 첨부파일을 가져옴
- 첨부파일이 어느 차량의 문서인지 알아냄
- 거래처가 별도 API를 호출하면 문서 다운로드 URL을 전달

<br>

#### 사용자 개입이 필요한 부분

- Work Mail API는 서비스 계정 토큰으로 호출할 수 없고 구성원 계정으로 인증받은 Access Token이 필요하기 때문에 사용자가 최초 한 번은 직접 로그인해야 함

<br>

#### 기능별 구현 방향

##### 1. Works 인증

- 관리자 페이지에 Works 계정 연결과 같은 버튼 생성

| 응답 | 처리 |
|-|-|
| 401/인증 오류코드 | 토큰 갱신 후 1회 재호출 |
| 403 | scope 또는 계정 권한 확인 |
| 500/502/503/504 | 일시 장애로 보고 재시도 |
| Refresh Token오류 | 자동 처리 중단 후 재로그인 알림 |


##### 2. 메일 수집 배치

- 5분마다 실행
- 대상 메일 판별 조건
  - 발신자, 말소사실 증명서가 포함되어 있는지, PDF 또는 이미지 첨부파일이 있는지 등(확실 X)
- 중복 처리 방지
  -  mailId + attachmentId에 Unique Key를 만드는 방식 고려

##### 3. 파일 저장

##### 4. 차량번호 추출과 신청 건 매핑

- PDF에서 차량번호 추출

##### 5. 거래처 제공 API

---

#### 개발 전 꼭 확정해야 할 사항

1. 공단 발신 이메일 주소가 고정인지
2. 메일 제목/본문/파일명 중 차량번호가 어디에 있는지
3. 암호화 PDF의 차량번호를 어떻게 추출할 수 있는지
4. 비밀번호를 시스템이 알 수 있는지
5. 말소사실증명서와 자동차 등록증이 같은 메일로 오는지
6. 같은 차량에 문서가 여러 번 올 수 있는지
7. 거래처별 인증 방식과 조회 권한
8. URL 만료시간과 원본 파일 보관기간
9. 자동 매핑 실패 건을 처리할 관리자 화면이 필요한지
10. Works 인증 계정은 무엇인지
