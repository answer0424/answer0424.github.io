## 파일 시스템의 개요와 종류

#### 개념과 특징

- 운영체제가 파일을 시스템의 디스크상에 구성하는 방식
- 컴퓨터에서 파일이나 자료를 쉽게 발견 및 접근할 수 있도록 보관 또는 조직하는 체제
- 하드 디스크나 CD-ROM과 같은 물리적 저장소를 관리
- 파일 서버 상의 자료로의 접근을 제공하는 방식과 가상의 형태로서 접근 수단만이 존재하는 방식도 파일 시스템의 범위에 포함
- 리눅스 파일 시스템의 구조

| 블록 | 설명 |
|-|-|
| Super Block | 해당 파일 시스템 관련 정보 저장 |
| Group Descriptor Table | 각 Block Group을 관리하는 정보 저장 |
| Block bitmap | 그룹 내에 있는 각 블록의 사용 상태를 나타냄 |
| inode | 파일에 대한 제어 정보 및 데이터 블록 포인터 저장 |

<br>

#### 리눅스 전용 디스크 기반 파일 시스템 

##### ext

- 리눅스 초기에 사용되던 파일 시스템이며 호환성이 없음

<br>

##### ext2

- ext 파일 시스템의 다음 버전
- 고용량 디스크 사용을 염두에 두고 설계된 파일 시스템

<br>

##### ext3

- ext2의 확장판
- 리눅스의 대표적인 저널링을 지원하도록 확장된 파일 시스템

<br>

##### ext4

- 파일에 디스크 할당 시 물리적으로 연속적인 블록을 할당
- 64비트 기억 공간 제한을 없앰
- 16 TeraByte의 파일을 지원

---

#### 저널링 파일시스템

- 시스템의 비정상적인 종료 시 저널을 이용해 빠르면서 안정적인 복구가 가능
- 데이터를 디스크에 쓰기 전에 로그에 데이터를 남겨 시스템의 비정상적인 셧다운에도 로그를 사용해 빠르고 안정적인 복구 기능을 제공하는 기술

| 파일 시스템 | 설명 |
|-|-|
| JFS(Journaling File Syetem) | IBM사의 독자적인 파일시스템 |
| XFS(eXetended File System) | 고성능 저널링 시스템, 64비트 주소를 지원하며 확장성이 있는 자료 구조와 알고리즘 사용 |
| ReiserFS | 리눅스용 저널링 파일시스템 중 가장 안정적이라는 평가를 받음 |

----

#### 네트워크 파일시스템

##### SMB

- 삼바 파일 시스템을 마운트 지정
- Server Message Vlock
- 윈도우 계열 OS 환경에서 사용된느 파일/프린터 공유 프로토콜

<br>

##### CIFS

- Common Internet File System
- SMB를 확장한 파일 시스템
- SMB를 기초로 응용하여 라우터를 뛰어넘어 연결할 수 있는 프로토콜

<br>

##### NFS

- Network File System
- 썬마이크로시스템이 개발한 네트워크 공유 프로토콜
- 파일 공유 및 파일 서버로 사용
- 공유된 영역을 마운트할 때 지정

---

#### 기타 지원 가능한 파일 시스템

##### FAT

- Windows NT가 지원하는 파일 시스템 중 가장 간단한 시스템
- FAT로 포맷된 디스크는 클러스터 단위로 할당
- 클러스터 크기는 볼륨 크기에 따라 결정
- 읽기 전용, 숨김, 시스템 및 보관 파일 특성만 지원


<br>

##### VFAT

- FAT 파일 시스템이 확장된 것
- FAT에 비해 제한이 적음

<br>

##### FAT32

<br>

##### NTFS

- 윈도우에서 사용하는 파일 시스템
- 안정성이 뛰어나고 대용량 파일도 저장
- 안정성, 자세한 사용자 제한, 보안성 등이 FAT32보다 뛰어남

## 관련 명령어

#### 명령어 mount와 umount

- 마운트는 특정 디바이스를 특정 디렉터리처럼 사용하기 위해 장치와 디렉터리를 연결하는 것
- 리눅스는 PnP 기능을 지원하지만 지원하는 하드웨어가 많지 않으므로 시스템 부팅 후에 수동으로 마운트해서 사용하고 사용이 끝난 후에 언마운트 시킴

```bash
mount [옵션] [디바이스명] [디렉터링명]
```

| 옵션 | 설명 |
|-|-|
| -a | /etc/fstab 파일에 정의된 모든 시스템 마운트 |
| -n | /etc/mtab 파일에 정보를 저장하지 않고 마운트 |
| -f | 실제 마운트하는 것이 아니라 마운트가 가능한지를 테스트 |
| -t(파일시스템) | |
| -o(추가설정) | |

<br>

```bash
umount [옵션] [디바이스명] [디렉터리명]
```

| 옵션 | 설명 |
|-|-|
| -a | 파일 /etc/fstab에 명시된 파일 시스템 마운트 해제 |
| -n | 파일 /etc/mtab 파일을 갱신하지 않고 마운트 해제 |
| -t | 언마운트할 파일 시스템을 지정 |

<br>

#### 명령어 eject

- 이동식 보조기억장치 등과 같은 미디어를 해제하고 장치를 제거하는 명령어

```bash
eject [옵션] [디바이스명]
```

| 옵션 | 설명 |
|-|-|
| -r | 시디롬을 마운트 해제 |
| -f | 플로피를 마운트 해제 |

<br>

#### 명령어 fdisk

- 새로운 파티션의 생성, 기존 파티션의 삭제, 파티션의 타입 결정 등의 작업을 수행할 수 있음
- fdisk 프로그램은 한 번에 한 다시크에 대해서만 작업을 수행
- fdisk는 명령어 프롬프트 중심의 매우 간단한 인터페이스를 가지고 있음

```bash
fdisk [옵션] [장치명]
```

| 명령어 | 설명 |
|-|-|
| -v | fdisk 버전 정보 표시 |
| -l | 현재 디스크의 파티션 테이블 정보 표시 |
| -s | 지정된 파티션의 크기를 블록 단위로 표시 |

- fdisk를 실행하기 위해서는 어떠한 디스크의 파티션을 나눌 것인지 알려주어야 함
- 하나의 컴퓨터에 여러 개의 하드디스크가 설치될 수 있으므로 어떤 하드디스크의 파티션을 변경할 것인지 알려주어야 함

| 명령어 | 설명 |
|-|-|
| p | 디스크 정보 표시 |
| n | 파티션 생성 |
| f | 파티션 속성 지정 |
| d | 파티션 삭제 |
| w | 변경된 파티션 정보 저장 |
| q | 파티션 설정 작업 종료 |

<br>

#### 명령어 mkfs

- 리눅스 파일 시스템을 생성
- fdisk로 하드디스크의 파티션을 나눈 후 해당 파티션에 맞는 파일 시스템을 생성

```bash
mkfs [옵션] 장치이름
```

| 옵션 | 설명 |
|-|-|
| -V | 자세한 정보 보기 |
| -t 파일 시스템 | 생성할 파일 시스템 타입을 지정 |
| -c || 파일 시스템을 생성하기 전에 배드블록을 검사 |
| -l 파일명 | 지정된 파일명으로부터 배드블록 목록 읽기 |
| -v | 작업 상태와 결과를 자세히 보기 |

<br>

#### 명령어 mke2fs

- ex2, ex3, ex4 타입의 리눅스 파일 시스템을 생성하는 명령
- fdisk 명령어로 파티션 작업을 한 후에 mkefs 혹은 mkfs 명령어로 파일 시스템을 생성

```bash
mke2fs [옵션] 장치명
```

| 옵션 |  설명 |
|-|-|
| -t | 파일 시스템 타입 지정 |
| -b | 블록 크기를 바이트 수로 지정 |
| -f | 프래그먼트 크기 지정 |
| -i | inode 당 바이트 수를 지정 |
| -j | 파티션을 저널링 파일 시스템 ex3으로 지정 |
| -R | RAID4 장치를 포맷할 때 사용하는 특수 옵션 |
| -R stripe은 RAID 장치에 적합한 데이터 구조 저장 |

<br>

#### 명령어 fsck

- 파일 시스템의 무결성을 점검하고 대화식으로 복구하는 명령어
- 파일 시스템 점검은 다음과 같은 여러 단계로 이루어짐
  - 오류에 대한 저널 로그의 점검
  - i-node, 간접 데이터 블록, 데이터 블록 그리고 메모리에 할당되지 않은 블록들을 리스트화한 빈칸 목록을 점검
  - 파일 크기의 점검과 디렉터리 항목을 점검
- 디렉터리 /lost+found은 fsck에서 사용하는 디렉터리
  - 손상된 파일을 /lost+found 디렉터리로 연결한 뒤에 오류를 수정하게 되며, 평상시에는 null 파일 링크에 의해서 비어있는 상태로 존재
  - 디렉터리 /lost+found에서 작업을 수행하다가 정상적으로 복구가 되면 파일은 사라짐

```bash
fsck [옵션] 장치명
```

| 옵션 | 설명 |
|-|-|
| -A | /etc/fstab에 표시된 모든 파일 시스템을 점검 |
| -a | 질의 없이 자동 복구 |
| -r | 질의 후 복구 |
| -s | fsck 동작을 시리얼화, 대화형 모드에서 여러 파일 시스템 점검 시 유용 |
| -t 파일 시스템 | 점검할 파일 시스템 유형 지정 |
