## 프로세스 조회, 분석

#### ps(Process Status)

- 현재 실행 중인 프로세스의 상태를 보여주는 명령어
- CPU 사용도가 낮은 순서로 출력

```bash
ps [옵션]
```

| 상태 | 설명 |
|-|-|
| PID | 프로세스 식별 번호 |
| TTY | 프로세스와 연결된 터미널 번호 |
|  TIME | 총 CPU 사용 시간 |
| CMD | 실행 명령어 |

| 옵션 | 설명 |
|-|-|
| a | 현재 실행 중인 모든 프로세스 출력 |
| e | 모든 프로세스 정보 |
| u | 사용자 이름과 프로세스 시작 시간 출력 |
| x | 접속된 터미널뿐만 아니라 사용되고 있는 모든 프로세스들을 출력 |
| l | 자세한 정보 출력 |

```bash
ps ax | grep httpd
```

| 상태 |  설명 |
|-|-|
| USER | 프로세스 소유자명 |
| PID | 프로세스 식별번호 |
| %CPU | CPU 사용 비율의 추정치 |
| %MEM | 메모리 사용 비율의 추정치 |
| VSZ | 페이지 단위의 가상 메모리 사용량 |
| RSS | 실제 사용된 메모리량 |
| TTY | 프로세스와 연결된 터미널 번호 |
| STAT | P: 수행 가능 / 수행 중 <br> R: 현재 실행 상태 <br> S: 잠든 상태 <br> D: I/O 작업이 끝나기를 기다리면서 정지된 상태 <br> T: 정지된 상태 <br> Z: 좀비 프로세스 |
| START | 프로세스 시작 시간 |
|  TIME | 총 CPU 사용시간 |
| COMMAND | 실행 명령어 |

- 좀비 프로세스는 kill 시그널을 받아도 종료되지 않음. 부모 프로세스가 정상적인 종료 처리를 하지 못해서 발생

```bash
ps -l
```

| 상태 | 설명 |
|-|-|
| F | 01: 주기억장치 내에 있음 <br> 02: 시스템 프로세스 <br> 04: 주기억장치 내에서 잠김 <br> 10: 스왑되고 있음 <br> 20: 다른 프로세스에 의해 추적되고 있음 |
| S | R: Running <br> T: Terminated <br> S: Sleeping <br> Z: Stopped <br> W: Waiting <br> I: Intermediated |
| UID | 프로세스 소유자의 Username |
| PPID | 부모 프로세스 PID |
| C | 짧은 시간 동안의 CPU 사용률 |
| PRI | 실행 우선순위 값, 값이 작을수록 우선순위가 높음 |
| NI | NICE 우선순위를 계산할 때 사용되는 nice 값 |
| ADDR | 프로세스의 주기억장치 내의 주소 |
| SZ | 프로세스 크기로 단위는 블록 |
| WCHAN | 프로세스가 대기나 수면 상태에서 기다리는 사건, 실행 중인 프로세스는 공백 |

<br>

#### pstree

- 명령어 pstree는 실행 중인 프로세스들을 트리구조로 나타냄

```bash
pstree [옵션]
```

| 옵션 | 설명 |
|-|-|
| -p | 프로세스 ID 표시 |
| -n | 프로세스 ID를 정렬해서 표시 |
| -a | 명령행 인자를 포함한 정보를 트리구조에 표시 |
| -h | 현재 프로세스와 해당 프로세스의 부모 프로세스를 음영으로 강조해서 표시 |

## 종료, 시그널 처리

#### kill

- 프로세스를 종료시킴

```bash
kill [옵션] [시그널 번호 또는 시그널 이름] [PID 또는 %작업번호]
```

| 옵션 | 설명 |
|-|-|
| -l | 시그널 종류 나열 |
| -s 시그널번호 또는 시그널명 | 전달할 시그널의 종류를 지정 |
| -1 | -HU, 프로세스를 재시작 |
| -9 | 프로세스를 강제 종료 |

<br>

#### killall

- 같은 데몬의 여러 프로세서를 한 번에 종료시킬 때 사용
- 프로세스 명으로 연관된 프로세스들을 종료시킴

```bash
killall [옵션] 프로세스명
```

| 옵션 |  설명 |
|-|-|
| -g | 그룹을 지정하여 프로세스를 종료 |
| -i | 프로세스 종료 전 확인 메시지를 표시 |
| -l | 시그널 목록 표시 |
| -v | 상세 정보 표시 |

## 우선순위, 모니터링

#### nice

- 프로세스 사이의 우선순위를 확인하고 우선순위를 변경할 수 있는 명령어
- NI 값을 조정하여 변경

```bash
nice [옵션] 프로세스명
```

| 옵션 | 설명 |
|-|-|
| -n 조정수치, -조정수치, --adjustment 조정수치 | 명령의 우선권에 조정수치를 더함 (-양수값, --음수값)|

- 조정할 수 있는 NI 값의 범위는 -20~19
- 우선순위 0의 값을 가지며 값이 작을수록 우선순위가 높음
- 옵션 -n을 사용하지 않으면 디폴트인 10을 사용
- 조정수치가 생략되면 명령의 우선권은 10만큼 증가
- 일반 사용자는 nice 값을 증가시킬 수 밖에 없으며, root는 nice 값을 감수시켜 우선순위를 높일 수 있음
- 명령어 `nice -10 bash`는 bash 프로세스 NI 값을 10만큼 증가시키는 것이며 값이 증가한다는 것은 우선순위를 낮추는 것 우선순위를 높이는 명령은 `nice --10 bash`임

<br>

#### renice

- 이미 실행중인 프로세스의 우선순위를 변경
- 프로세스 소유자와 루트 권한자만이 명령을 내릴 수 있음

```bash
renice [옵션] NI값 PID
```

| 옵션 | 설명 |
|-|-|
| -p | 프로세스 ID 지정 |
| -u | 사용자명 지정 |
| -g | 프로세스의 GID 지정 |

- 우선순위 변경 시 프로세스 ID, 사용자명, 프로세스 그룹 ID를 사용
- 명령어 nice는 기존 NI값을 증감시키지만, 명령어 renice는 지정한 NI값을 지정
- nice는 양수값에 -, 음수값에 --를 사용하지만 renice는 양수값에 -를 사용하지 않음
- 명령어 `renice -20 3241`은 프로세스 3241의 NI값을 -20으로 변경

<br>

#### top

- 리눅스 시스템의 운영 상태를 실시간으로 모니터링하거나 프로세스 상태를 확인할 수 있음

```bash
top [옵션] [PID]
```

| 옵션 | 설명 |
|-|-|
| -d 시간 | 실시간 화면 출력 시간 지정 |
| -p PID | 모니터할 프로세스 지정 |

| 상태 |  설명 |
|-|-|
| PID | 프로세스 식별자 번호 |
| USER | 프로세스 소유자 |
| PR | 프로세스 우선순위 |
| NI | 프로세스의 nice값 |
| VIRT | 해당 프로세스가 사용하는 가상 메모리의 총량 |
| RES | 해당 프로세스의 물리적 메모리 사용량 |
| SHR | 해당 프로세스에 의해 사용된 공유 메모리 총량 |
| S | D: 중단될 수 없는 Sleep 상태 <br> R: 실행 중인 상태 <br> S: 휴면 상태 <br> T: Trace되거나 정지된 프로세스 <br> Z: 좀비프로세스 |
| %CPU | 해당 프로세스의 CPU 사용률 |
| %MEM | 해당 프로세스의 메모리 사용률 |
| TIME+ | 100분의 1초 단위로 나타내는 CPU 사용시간 |

- 기본적으로 5초에 한번씩 실시간으로 시스템 상태 정보가 갱신됨

## 작업 제어

#### jobs

- 작업이 중지된 상태, 백그라운드로 진행중인 상태, 변경되었지만 보고되지 않은 상태 등을 표시

```bash
jobs [옵션] [작업번호]
```

| 옵션 | 설명 |
|-|-|
| -l | 프로세스 그룹 ID를 state 필드 앞에 표시 |
| -n | 프로세스 그룹 중 대표 프로세스 ID 표시 |
| -p | 프로세스 ID를 한 행씩 표시 |

- 출력된 목록에서 `+`는 현재 작업 실행, `-`는 앞으로 실행될 작업을 나타냄

| 상태 | 설명 |
|-|-|
| Running | 작업이 일시 중단되지 않았고 종료하지 않고 계속 진행 중 |
| Stopped | 작업이 일시 중단 |
| Done | 작업이 완료되어 0을 반환하고 종료 |
| Done(code) | 작업이 정상적으로 완료되었으며, 0이 아닌 코드르 반환 |

<br>

#### bg와 fg

##### 포어그라운드에서 백그라운드로의 전환

- 명령어 bg는 현재 실행 중인 프로세스를 백그라운드 작업으로 전환

```bash
bg %작업번호 또는 bg 작업번호
```

- 작업이 빨리 끝날 것이라고 예상하고 실행했지만 시간이 지나도 끝나지 않을 때 또는 현재 작업을 유지한 상태로 다른 작업을 실행하고 싶을 때 백그라운드로 전향해서 작업을 진행하는 경우가 있음
- 포어 그란운드에서 백그라운드로 전환 시 먼저 실행 중인 작업을 중지시키 후 bg 명령을 실행할 수 있음

<br>

##### 백그라운드에서 포어그라운드로의 전환

- 명령어 fg는 현재 백그라운드로 실행 중인 명령어를 포어그라운드로 전환

```bash
fg %작업번호 또는 fg번호
```

- 작업번호를 부여하지 않으면 현재 수행중인 작업을 포어그라운드로 전환

## 백그라운드 지속, 출력 확인

#### nohup

- 프로세스가 중단되지 않고 백그라운드로 작업을 수행할 수 있게 함
- 사용자가 로그아웃하거나 작업 중인 터미널 창이 닫혀도 실행 중인 프로세스를 백그라운드 프로세스로 계속 작업할 수 있도록 함
- 용량이 큰 데이터 압축 해제와 같은 실행 시간이 오래 걸리는 프로세스들에 대해 nohup으로 처리하여 작업하면 작업 중단없이 해당 업무를 완료할 수 있음
- 백그라운드로 실행될 수 있는 명령행 뒤에 `&`를 명시

```bash
nohup tar cvf source. tar /opt/src &
[1] 4562
```

<br>

#### 명령어 tail

- 파일의 마지막 행을 기준으로 지정한 행까지 파일 내용의 일부를 출력
- 기본값으로 마지막 10줄을 출력

```bash
tail [옵션] [파일명]
```

| 옵션 | 설명 |
|-|-|
| -f | 파일의 10중을 출력하고 파일의 내용을 실시간으로 출력 |
| -n N | N 개수만큼의 라인을 출력 |

## 스케줄링

#### 리눅스에서의 스케줄링

- 주기적으로 반복되는 작업을 자동으로 실행하도록 설정하는 기능
- 이를 담당하는 스케줄링 데몬은 crond이며, 부팅 시 자동으로 실행되어 예약된 작업들을 주기적으로 수행
- crond의 설정 파일은 /etc/crontab으로 시스템 전체에 공통으로 적용되는 작업을 정의

<br>

#### 사용자 스케줄링

- 사용자는 crontab 명령어를 통해 자신만의 주기적 작업을 등록, 관리할 수 있음

```bash
crontab [옵션] 파일명
```

| 옵션 | 설명 |
|-|-|
| -l | crontab에 설정된 내용 출력 |
| -e | crontab을 작성하거나 수정 |
| -r | crontab 내용 삭제 |
| -u | 특정 사용자의 일정 수정 |


| 분 | 시 | 날 | 달 | 요일 | 명령어 |
|-|-|-|-|-|-|
| * | 4 | * | * | 2,4 | /etc/backup.sh |

- 해당 백업 파일은 매주 화요일과 목요일 오전 4시에 실행됨
