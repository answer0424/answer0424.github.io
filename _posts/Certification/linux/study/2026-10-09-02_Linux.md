# 리눅스 일반

## 파티션

#### 파티션의 특징과 종류

- 주 파티션
- 확장 파티션
- 파티션을 4개 이상 만들고 싶다면 3개의 주 파티션을 만들고 확장 파티션에 추가하면 됨

<br>

#### 파일 시스템

- 하드디스크를 편하게 사용
- 하드디스크에 어느 부분에 어떤 데이터를 저장할 건지 위치를 기록
- 파일 시스템 유형
  - 리눅스 전용 파일 시스템: ext, ext2, ext3, ext4
  - 저널링 파일 시스템: JFS, XFS, ReiserFS
  - 네트워크 파일 시스템: SMB, CIFS, NFS
  - 클러스터링 파일 시스템: 레드헷 GFS, SGI, cXFS, IBM, GPFS, IBM SanFS, EMC, highroad, Compaq CFS, Veritas CFS, 오라클 OCFS2
  - 시스템 파일 시스템: ISO9660, UDF
  - 타 운영체제 지원 파일 시스템: FAT, VFAT, FAT32, HPFS, SysV

<br>

#### LVM(Logical Volume Manager)

- LVM을 사용하면 2개의 디스크를 하나로 합쳐서 하나인 것처럼 사용할 수 있음
- 각각의 하드디스크를 PV(Physical Volume)으로 인식
- PV는 하드디스크를 PE라는 작은 단위로 나눠줌
- 관리자는 원하는만큼 PE를 가져와서 LV라는 Logical Volume을 만듦

<br>

#### RAID(Redundant Array of Independent)

- LV를 구성하는 방식
- RAID0: 성능만을 위한
  - 하나의 파일을 두개의 디스크에 나눠서 저장
  - 예를 들어서 Disk0과 Disk1이 있다면 두개의 파일을 동시에 저장할 수 있음
  - 또한 특정 파일을 불러올 때도 데이터를 읽는 속도도 두배임
  - 디스크가 많을 수록 빨라짐
  - 디스크 중 하나만 고장이 나더라도 특정 파일의 내용을 잃어버리게 되어서 파일을 불러올 수 없음
- RAID1: 안정성만을 위한
  - 하나의 파일을 두개의 디스크에 똑같은 데이터를 저장
  - 디스크를 두개나 세개를 써도 동일한 속도
  - 디스크가 고장났을 때 파일을 읽을 수 없는 문제가 발생하지 않음
- RAID5: 0, 1의 장점만을 가져온
  - 예를 들어 특정 파일을 Disk0, 1, 2에 나눠서 저장하고 Disk3에 특정 문제가 발생을 하더라도 복구가 가능하도록 Parioty bit를 저장
  - 속도도 빠르면서 특정 디스크에 문제가 발생했을 때 파일을 복구할 수 있음
  - 하지만 다른 RAID보다 디스크가 많이 필요

<br>

#### 부트매니저

> BIOS -> MBR -> BOOT Loader(GRUB) -> Kernel -> Systemd -> Login Shell

##### BIOS

- 각 부품을 연결시켜주는 메인보드에 위치
- ROM이라는 곳에 BIOS가 저장
- PC의 전원을 켜면 가장 먼저 동작
- 각종 하드웨어가 정상적으로 연결되어 있는지 점검
- 하드디스크의 가장 첫번째 공간에서 MBR이라는 것을 찾아서 실행

<br>

##### MBR

- MBR은 부트코드와 파티션 테이블에 대한 정보를 기억하고 있음
- MBR에서 부트로드를 읽어서 실행을 하게 됨

<br>

##### BOOT Loader(GRUB)

- 부트로더가 리눅스 커널의 목록을 보여줌
- 선택된 리눅스 커널로 리눅스가 실행됨

<br>

##### Kernel

- 리눅스 커널은 하드웨어 장치를 인식하고 초기화
- 부팅이 된 리눅스는 실행되어야 하는 첫번째 프로그램을 실행

<br>

##### Systemd

- 부팅이 된 리눅스가 가장 먼저 실행되는 프로그램
- PID는 1번임
- 다른 프로그램들을 실행해줌
- Systemd가 관리하는 프로그램들은 `/etc/systemd/system`에서 확인할 수 있음

<br>

##### Login Shell

- Systemd에 의해서 마지막으로 실행이 됨
